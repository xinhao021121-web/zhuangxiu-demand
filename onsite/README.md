# 问需 · 现场（PWA）

设计师在量房现场用手机打开的应用：**选单 → 出门前过一遍 → 逐空间问 → 记一笔 / 没问上 → 量房记录**（F7–F11）。

## 起服务

```bash
pnpm install --dir onsite --ignore-workspace   # 依赖按包安装，不动仓库根目录
pnpm run onsite:dev                            # http://127.0.0.1:5174（另起一个终端跑 pnpm run api:dev）
pnpm run onsite:build                          # 产物：onsite/dist
```

手机上访问时用局域网地址（`vite dev --host`）或部署后的域名；装到主屏幕即可离线打开。

## 离线是怎么做的

三层，缺一不可：

| 层 | 做法 | 解决什么 |
| --- | --- | --- |
| 应用外壳 | `public/sw.js` 预缓存 `/`、`/index.html` 与图标 | 断网也能打开，不会看到浏览器的错误页 |
| 业务数据 | 在线时把清单存进 IndexedDB；断网时读本地缓存 | 现场没信号也看得到这一家的清单 |
| 现场记录 | 先写 IndexedDB 并标「待同步」，回到有网自动推送 | 记录不会因为没网丢掉 |

接口一律不缓存：清单与记录都走服务端，离线时由本地库兜住，避免「看到的是过期缓存」这种更难查的问题。

## 为什么是独立工程

桌面端要的是服务端渲染与一体化部署，现场端要的是离线优先与单手操作，两者的构建、缓存与离线策略互相迁就，
所以按技术方案 2.3 拆成两个工程。**不共用界面，但共用判断**：清单判据、统计、速记拼装都来自 `packages/*`。
