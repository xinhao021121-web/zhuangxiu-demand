# Demo 使用说明（V0.2）

## 打开哪个文件

打开 `装修需求发现助手_Demo_V0.2.html`，双击即可，不需要起服务器，也不需要联网。数据全部模拟，填写进度存在浏览器本地，右上角「重置」可清空。

第一次打开建议点「填入示例需求」，会灌入一个 89㎡ 旧房翻新、三口之家养猫、两个卫生间的场景，右侧助手会立刻推出一批建议。

## 这一版做对了什么

- **空间可增删**：其他卧室（≤4）、卫生间（≤3，默认主卫与客卫）、书房与电竞房（≤2）。其他卧室只在需要时才添加，添加后先选房型，再显示对应字段。
- **房型决定字段**：一间次卧选「儿童房」只显示儿童房相关的字段，选「长辈房」显示适老字段，不会出现无关问题。
- **每个大类都有「其他补充」**：助手采纳的建议写回建议所属大类的「其他补充」，而不是全部堆到全局说明里，字段旁带「助手建议 · 撤销」标记。
- **没有必填项**：顶部显示的是「需求清晰度」（推荐项完成度），跳过任何字段都不会被拦住。

## 为什么不要打开 `_demo_template.html`

模板文件放在 `tools/_demo_template.html`，里面字段数据是空的，它只是构建中间产物。直接打开只会看到提示，而且会和 Demo 共用同一份浏览器本地存储，出现"左侧空白但右侧有发现"的错乱现象。

## 怎么重新生成

字段规格来自 `outputs/01a0c95f-3b4f-7762-ad52-61bb13941fcc/装修需求采集表_字段清单_V2.xlsx`，构建脚本把字段数据注入模板：

```
python tools/build_demo.py
```

改了字段清单或模板后重新执行即可，Demo 与字段规格不会漂移。

## 怎么验证

```
node tests/demo.smoke.mjs
```

用无头 Chromium 跑完整链路：初始结构校验 → 添加次卧 → 选房型后动态字段 → 填入示例 → 定位与采纳 → 改一改 → 撤销 → 连续忽略进静默 → 恢复 → 需求摘要 → 提交前检查 → 删除实例 → 重置，另外回归验证直接打开模板文件时不会出现空白页与 NaN。
