# 小程序端 Demo 使用说明（V0.1）

这是「问需 · 采集」的小程序端界面 Demo：手机优先，纯前端，没有后端，数据全部模拟。

## 打开哪个文件

打开 `装修需求发现助手_小程序端Demo_V0.1.html`，双击即可，不需要起服务器，也不需要联网。

- 手机上打开：整屏铺满，就是小程序的真实观感。
- 电脑上打开：自动收成手机宽度（430px）居中显示，方便截图和演示。

数据只存在本机浏览器，刷新后仍在。想清空，滚到表单最底部点「重置全部内容」。

第一次打开点「填入示例需求」，会灌入 89㎡ 旧房翻新、三口之家养猫、两个卫生间的场景，右下角助手立刻给出建议。

## 移动端信息架构

和 PC 版 Demo 的左右分栏不同，手机端重新安排了信息层级：

| 位置 | 内容 |
| --- | --- |
| 顶部导航栏 | 小程序风格标题栏 + 胶囊按钮区 |
| 顶部进度 | 需求清晰度进度条（推荐项完成比例） |
| 顶部分区导航 | 13 个大类横向滑动，带完成状态点，点击跳转并展开 |
| 表单主体 | 大类手风琴，一次只展开一个；折叠时显示已填数量 |
| 底部发现横条 | 需求发现助手入口，常驻显示「还有 N 条发现值得看一眼」 |
| 底部操作栏 | 自动保存状态 + 提交设计师，适配安全区 |
| 底部弹层 | 发现列表，可下滑关闭、上滑全屏 |
| 整页摘要 | 需求摘要用整页展示，方便阅读和复制 |

## 这一版为手机做的取舍

- **手风琴代替长列表**：191 个字段一屏铺开在手机上无法导航，改成一次只展开一个大类。
- **按需渲染**：折叠的大类不生成 DOM，只渲染展开的那一个，避免长表单卡顿，也贴合小程序 `setData` 要少传数据的约束。
- **侧边栏变底部横条**：PC 上常驻的 360px 侧栏在手机上放不下，改成底部常驻的发现横条 + 半屏弹层，随时看得到待办，又不遮挡表单。
- **摘要整页展示**：手机上小弹窗读长文本体验差，改成整页滑出，底部常驻复制。
- **抽屉手势**：发现弹层支持下滑关闭、上滑到全屏，遵循手机的下拉手势习惯。
- **触控尺寸**：可点击控件高度均不小于 32px，大类头部 52px，底部主按钮 42px。
- **重新排序**：发现卡片按 P0 → P1 → P2 排序，风险提醒优先。
- **已处理不消失**：采纳或忽略后卡片变绿下沉到「最近处理」，让用户看得到处理结果。

## 怎么重新生成

字段规格来自 `outputs/01a0c95f-3b4f-7762-ad52-61bb13941fcc/装修需求采集表_字段清单_V2.xlsx`，构建脚本把字段数据注入模板：

```
python tools/build_mobile_demo.py
```

改了字段清单或模板后重新执行即可，Demo 与字段规格不会漂移。

不要直接打开 `tools/_mobile_template.html`（构建中间产物，字段数据是空的）。

## 怎么验证

```
node tests/mobile.smoke.mjs
```

用无头 Chromium 模拟 390×844 手机，跑完整链路：字段规格完整性 → 首屏结构 → 移动端布局指标 → 手风琴 →
分区导航 → 空间实例增删与房型联动 → 示例数据与发现列表 → 定位跳转 → 采纳 / 改一改 / 撤销 →
连续忽略进静默 → 恢复 → 需求摘要 → 提交前检查 → 删除实例 → 重置，并回归模板文件不出现空白页与 NaN。

其中布局指标包含：无横向溢出、发现横条与操作栏不重叠、底部常驻区贴住屏幕底部、发现横条触控高度、
可点击控件高度、折叠头部高度一致、滚到底部时内容不被底部栏遮挡、弹层打开时横条被遮挡不会误触。
截图输出在 `mobile/screenshots/`。

如果本机的 Playwright 自带 Chromium 无法启动（缺少运行库时会报 side-by-side 配置错误），
测试会自动回落到系统已安装的 Chrome 或 Edge；也可以手动指定：

```
$env:PLAYWRIGHT_CHROMIUM="C:/Program Files/Google/Chrome/Application/chrome.exe"; node tests/mobile.smoke.mjs
```
